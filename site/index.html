How it works

A rhythm brawler where the chord you hold is your guard and the beat decides if a strike lands.

1

Chord stances

L1, L2, R1 and R2 combine into a 4-bit mask, sixteen possible guards. Today the move table resolves the empty chord and each single button.

2

Beat judgment

A flick is judged by its distance to the nearest beat in whole frames: perfect, good or miss. Good hits score 60% of perfect, and a miss costs stamina.

3

Rollback on a ledger

Every action is stored in an in-memory Joltrin B-tree. When a predicted opponent input turns out wrong, the ledger reverts and the match resimulates from the corrected input.

Run it

Go 1.26 or later. This is a command-line slice, not the full game.

git clone https://github.com/gerardrecinto/resonant-strike
cd resonant-strike
go run ./cmd/demo
go test ./...
rollback/   frame ledger and state types
combat/     chord and timing to move and damage
cmd/demo/   scripted match with a real rollback

Rollback and the adaptive AI are built on Joltrin, an embedded Go storage engine.

What this does not do
  • It is a prototype slice. There is no rendering, no audio sync, no networking and no input device handling yet.
  • The adaptive AI described in the docs is designed, not built. Nothing here uses it.
  • Strength does not scale damage yet, and the 16-chord table is not filled in. The README says so too.
